# 1. 需求规格说明书

## 1.1 项目背景

用户日常在拼多多、京东、淘宝三个平台购物，包裹数量多、物流更新频繁。
现有购物 App 的物流通知存在两个问题：
1. **通知过多** —— 每个中转节点都推送，造成通知疲劳
2. **跨平台分散** —— 需要分别打开三个 App 查看

本项目的目标：**一个微信小程序，集中跟踪所有包裹，只在关键节点推送通知。**

## 1.3 功能列表

### F1: 多平台账号绑定

| 功能 | 描述 |
|---|---|
| F1.1 | 用户在淘宝中点击「绑定拼多多」，后端 Playwright 打开拼多多登录页生成二维码 |
| F1.2 | 小程序轮询二维码状态，检测用户是否扫码 |
| F1.3 | 扫码成功后保存 cookie/Session，标记账号已绑定 |
| F1.4 | 显示绑定状态：已绑定 / 已过期 / 未绑定 |
| F1.5 | 每日自动检测 Session 有效性，过期后提示重新扫码 |

### F2: 自动订单同步

| 功能 | 描述 |
|---|---|
| F2.1 | 每天 3 次（08:00/14:00/20:00）自动同步各平台近 3 个月订单 |
| F2.2 | 识别未签收/未归档的订单，提取运单号和快递公司 |
| F2.3 | 新运单自动加入物流跟踪队列 |
| F2.4 | 已签收超过 7 天的订单自动归档 |

### F3: 物流跟踪

| 功能 | 描述 |
|---|---|
| F3.1 | 每 2 小时通过快递100 API 查询一次运单状态 |
| F3.2 | 记录完整的物流轨迹时间线 |
| F3.3 | 状态变更检测引擎：静默节点 vs 关键节点分类 |

### F4: 智能通知

| 功能 | 描述 |
|---|---|
| F4.1 | 到达目的地城市 → 推送微信订阅消息 |
| F4.2 | 已签收 → 推送微信订阅消息 |
| F4.3 | 物流异常（滞留 3 天以上 / 退回） → 推送微信订阅消息 |
| F4.4 | 其他所有中转节点 → 静默记录，不推送 |
| F4.5 | 同一包裹 24 小时内不重复推送相同状态 |
| F4.6 | 免打扰时段内（默认 22:00-08:00）消息延迟到 08:01 发送 |
| F4.7 | 用户可自定义免打扰时段 |

### F5: 包裹管理

| 功能 | 描述 |
|---|---|
| F5.1 | 包裹列表：显示所有进行中的包裹（按更新时间倒序） |
| F5.2 | 包裹详情：显示完整物流轨迹时间线 |
| F5.3 | 包裹卡片：显示商品名称、快递公司、运单号、当前状态 |
| F5.4 | 手动删除包裹 |
| F5.5 | 包裹搜索（按商品名/运单号） |

### F6: 数据统计

| 功能 | 描述 |
|---|---|
| F6.1 | 月度收件趋势图 |
| F6.2 | 各平台包裹数量占比 |
| F6.3 | 快递公司使用频率分布 |

## 1.4 非功能需求

### 性能
| 需求 | 指标 |
|---|---|
| 小程序首页加载 | ≤ 2 秒 |
| 物流状态查询 | ≤ 3 秒（含三方 API 调用） |
| 通知推送延迟 | 状态变更后 ≤ 5 分钟推送（非免打扰时段） |
| Playwright 订单同步 | 单平台 ≤ 3 分钟/次 |

### 可靠性
| 需求 | 指标 |
|---|---|
| 定时任务执行成功率 | ≥ 99% |
| 快递100 API 调用可用 | 失败自动重试 3 次，间隔 30 秒 |
| Session 过期检测 | 每日检查，过期后 24 小时内提示用户 |

### 安全
| 需求 | 说明 |
|---|---|
| 平台 cookie 加密存储 | 云数据库中对 cookie 字段加密（AES-256） |
| 不存储用户密码 | 全程仅使用 QR 扫码登录 |
| 微信订阅消息授权 | 首次使用时申请授权，每次推送需要有效授权 |
| Token 有效期 | 平台 cookie 持久化存储，但支持用户主动解绑 |

### 隐私
| 需求 | 说明 |
|---|---|
| 最小数据采集 | 仅收集运单号、快递公司、商品名、物流状态 |
| 数据删除 | 用户可一键清除所有数据并解绑所有平台 |
| 数据隔离 | 不同用户的数据完全隔离 |

## 1.5 约束条件

| 约束 | 说明 |
|---|---|
| 技术栈 | Node.js + 微信云开发（CloudBase） |
| 运行环境 | CloudBase 云函数 + 云托管（Docker） |
| 物流 API | 快递100 免费 API（个人认证，日限 100 次） |
| 通知方式 | 微信小程序订阅消息（一次性订阅，每次推送需要用户预先授权） |
| 浏览器自动化 | Playwright + stealth 插件 |
| 代码托管 | GitHub（https://github.com/ynmcgm/logistics-tracker.git） |

## 1.6 平台接入优先级

| 优先级 | 平台 | 理由 |
|---|---|---|
| P0 | 拼多多 | 移动网页版结构简单，反爬较弱 |
| P1 | 京东 | 桌面版+移动版结构化，中等难度 |
| P2 | 淘宝 | 反爬最严，需更多对抗手段 |

## 1.7 术语表

| 术语 | 说明 |
|---|---|
| 订阅消息 | 微信小程序能力，用户授权一次后可发送一条模板消息 |
| CloudBase | 腾讯云·微信云开发，提供云函数、云数据库、云托管 |
| 云托管 | CloudBase 的 Docker 容器托管服务，用于运行 Playwright |
| Session | 用户在某平台的登录态（cookie），持久化后用于免登录抓取 |
| 关键节点 | 「到达目的地城市」「已签收」「物流异常」 |
| 静默节点 | 中转站/运输中/已揽收等其他状态 |
