## 2.2 核心组件说明

### 2.2.1 小程序前端 (miniprogram/)

| 页面 | 功能 | 数据源 |
|---|---|---|
| 首页 | 包裹列表，按状态分组（运输中/待取/已完成） | 云数据库 parcels |
| 绑定页 | QR 扫码绑定各平台账号 | 云函数 api-gateway |
| 详情页 | 单个包裹的物流时间线 | 云数据库 tracking_records |
| 设置页 | 免打扰时段、通知开关、账号管理 | 云数据库 |
| 统计页 | 月度统计图表 | 云函数 (aggregation) |

### 2.2.2 API 网关 (cloudfunctions/api-gateway/)

所有小程序前端请求的入口，提供 RESTful 接口。

| 接口分组 | 说明 |
|---|---|
| `/auth/*` | 账号绑定、解绑、状态查询 |
| `/parcels/*` | 包裹 CRUD、列表、详情 |
| `/settings/*` | 用户配置读写 |
| `/stats/*` | 统计数据 |
| `/engine/*` | 触发引擎同步（手动触发） |

### 2.2.3 Playwright 自动化引擎 (engines/)

运行在 CloudBase 云托管（Docker）中的 Node.js 应用。

| 模块 | 功能 |
|---|---|
| `common/browser.js` | Chromium 浏览器池管理，单例模式 |
| `common/qr-login.js` | QR 码生成、扫码状态轮询 |
| `common/session.js` | Cookie 序列化/反序列化，持久化存储 |
| `common/stealth.js` | Playwright 反检测配置 |
| `pdd/index.js` | 拼多多引擎入口（调度 login → orders → parser） |
| `pdd/login.js` | 拼多多扫码登录流程 |
| `pdd/orders.js` | 拼多多订单页面抓取 |
| `pdd/parser.js` | 订单页 HTML 解析，提取运单号 |

### 2.2.4 物流跟踪 (cloudfunctions/tracking-worker/)

由 CloudBase 定时触发器驱动的云函数。

```
定时触发（每2小时）
    │
    ▼
从 parcels 表读取所有"跟踪中"的包裹
    │
    ▼
调用快递100 API 查询最新状态
    │
    ▼
状态变更检测引擎
    ├── 无变化 → 更新 last_check_time，跳过
    ├── 到达目的地城市 → 写入 notification_queue 触发推送
    ├── 已签收 → 写入 notification_queue 触发推送
    ├── 物流异常 → 写入 notification_queue 触发推送
    └── 其他节点 → 写入 tracking_records，不推送
```

### 2.2.5 通知推送 (cloudfunctions/notification-sender/)

从通知队列读取待发送的通知，调用微信订阅消息 API。

```
触发条件
    │
    ▼
检查免打扰时段
  ├── 在免打扰时段内 → 标记 delayed，下次再发
  └── 不在免打扰时段内
        │
        ▼
检查用户是否授权了该消息模板
  ├── 未授权 → 记录日志，跳过
  └── 已授权
        │
        ▼
调用微信订阅消息 API 发送
        │
        ▼
记录发送日志到 notify_log 表
```

## 2.4 技术选型决策

| 决策 | 选项 | 选择 | 理由 |
|---|---|---|---|
| 运行环境 | 云函数 vs 云托管 | **两者都用** | 云函数处理轻量 API/定时任务；云托管运行 Playwright（需 Chromium） |
| 数据库 | MongoDB (CloudBase) | **云数据库** | CloudBase 原生集成，自动扩缩容 |
| 定时任务 | CloudBase 定时触发器 | **采用** | 原生支持的 cron 表达式 |
| 消息推送 | 订阅消息 vs 客服消息 | **订阅消息** | 订阅消息通道独立，不依赖用户最近交互 |
| 反检测 | playwright-stealth | **采用** | 社区最成熟的 Playwright 反检测插件 |
| 物流 API | 快递100 vs 快递鸟 | **快递100** | 免费额度清晰，API 文档完善，覆盖快递公司全 |
| 部署 | CloudBase CLI | **采用** | 官方部署工具，与微信生态集成最好 |

## 2.6 免打扰实现策略

```
┌─────────────────────────────────────────────┐
│              通知调度器                         │
│                                               │
│  incoming_notification                        │
│        │                                      │
│        ▼                                      │
│  ┌─────────────┐                              │
│  │ 是免打扰时段？  │─── 是 ──► 写入 delayed_queue │
│  └──────┬──────┘                              │
│         │ 否                                  │
│         ▼                                    │
│  ┌─────────────┐                              │
│  │ 发送频率检査   │─── 超限 ──► 写入 delayed_queue │
│  └──────┬──────┘                              │
│         │ 正常                                │
│         ▼                                    │
│    发送通知                                    │
└─────────────────────────────────────────────┘

delayed_queue (每1分钟检查一次):
  - 当前时间已退出免打扰时段
  - 频率配额已刷新
  → 取出最旧的 N 条发送
```

## 2.7 错误处理策略

| 组件 | 错误 | 处理方式 |
|---|---|---|
| Playwright 引擎 | 登录超时 | 重试 2 次，仍失败则标记 session 过期 |
| Playwright 引擎 | 页面元素未找到 | 截图保存到云存储 + 日志报警 |
| 快递100 API | HTTP 5xx | 指数退避重试：30s → 60s → 120s |
| 快递100 API | 频率超限 | 跳过本轮，下次定时周期再查 |
| 微信订阅消息 | 用户取消授权 | 记录日志，后续不再尝试推送（用户重新授权前） |
| 云函数 | 执行超时 | 拆分任务：每 50 个包裹为一个批次 |

## 2.8 安全策略

1. **Cookie 加密**：平台登录 cookie 在写入云数据库前用 AES-256 加密
2. **最小权限原则**：每个云函数只授予其需要的数据读写权限
3. **请求鉴权**：所有 API 接口校验微信用户的 openid，防止越权访问
4. **敏感操作日志**：绑定/解绑/删除数据等操作记录操作日志
